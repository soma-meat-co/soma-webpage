1. Arquitectura en capas

Toda operación atraviesa las mismas cuatro capas, siempre en este orden. Ninguna capa salta a otra que no sea la siguiente.

Componente (navegador)          src/app/DMS/**/xxxComponent.tsx, src/components/DMS/*
   │  llama
   ▼
Server Action ('use server')    src/app/DMS/**/xxx.actions.ts
   │  llama
   ▼
Provider (interfaz) ← Service   src/lib/core/<módulo>/provider/*.provider.ts   (contrato)
                                src/lib/core/<módulo>/service/*.service.ts     (implementación)
   │  usa
   ▼
Supabase (Postgres + RLS)  /  Cloudflare R2
CapaResponsabilidadLo que no hace
Componente clienteEstado de la UI, llamar actions, hacer el PUT del archivo a R2, mostrar message de error.No importa SDKs de Supabase ni de R2. No decide permisos.

Base de datos dbGuarda datos y decide permisos con RLS.—

Reglas que se cumplen en todo el módulo

  • Los permisos los decide RLS. Los services usan el cliente con la sesión del usuario (createSupabaseServerClient), así que Postgres evalúa las políticas como ese usuario. La UI solo oculta lo que el usuario no puede usar.
  • Las credenciales nunca llegan al navegador. Las claves de R2 viven en privateEnv y solo las usa storage.service.ts, marcado con import 'server-only'.
  • Cada service se exporta como una instancia del provider: documentsProvider, areasProvider, storageProvider. El resto del código depende de la interfaz, no de la clase.
  • Las actions nunca lanzan. Next reemplaza el mensaje de los errores lanzados en producción, así que el único modo de mostrar un mensaje útil es devolverlo.

2. Flujos

2.1 Subir un documento

Punto de entrada: handleUpload() en src/app/DMS/documents/uploadDocumentsComponent.tsx, al presionar "Subir".

La fila en la base de datos se crea antes que el archivo en R2. Si la subida falla a la mitad, queda una fila pendiente (localizable desde la base de datos) en lugar de un archivo sin registro.

  1. cliente Validación local. Si no hay archivo, o isSupportedFileType(file.type) es falso, muestra error y se detiene. Pasa uploadStatus a "uploading".
  2. action uploadDocument({ name, description, fileType, fileSize })
    src/app/DMS/documents/documents.actions.ts
    1. service documentsProvider.createPendingDocument(input):
      • supabase.auth.getUser() → sin sesión: AuthError 401.
      • supabase.rpc('has_full_document_access') → falso: AccessError 403.
      • Genera id = crypto.randomUUID() y key = storageProvider.createDocumentKey(id, fileType) → documents/<id>.pdf.
      • INSERT en documents con uploaded_at = NULL (pendiente) y uploaded_by = user.id. Si el id choca (23505), genera otro; hasta 3 intentos.
      • Devuelve { id, key }.
    2. service storageProvider.createUploadUrl({ key, contentType, size }): firma un PUT a R2 válido 5 minutos, con content-type y content-length incluidos en la firma.
    3. Devuelve { ok: true, uuid: id, signedUrl: { url, expiresAt } }.
  3. cliente PUT directo a R2. fetch(signedUrl.url, { method: "PUT", body: file, headers: { "Content-Type": file.type } }). El cuerpo es el File tal cual (sin FormData) para que el navegador ponga el Content-Length exacto. Si !response.ok, error "No se pudo subir el archivo".
  4. action confirmUploadedDocument(uuid)
    src/app/DMS/documents/documents.actions.ts
    service documentsProvider.confirmUpload(id): UPDATE documents SET uploaded_at = now() WHERE id = $1 AND uploaded_at IS NULL, pidiendo la fila de vuelta. 0 filas → DocumentError.UploadNotPending 404. Confirmar dos veces no cambia nada.
  5. cliente Muestra la card. Guarda { id, name, fileType } en el estado uploaded, lo que reemplaza el formulario por <UploadedDocumentCard>.

Estados de la UI (UploadStatus): "idle" → "uploading" → "success" | "error". El botón se deshabilita en "uploading"; el mensaje de error solo se muestra en "error".

2.2 Asignar un área a un documento

Punto de entrada: el <select> de src/app/DMS/documents/uploadedDocumentCard.tsx. Elegir una opción dispara handleAssign(areaId).

  1. cliente handleAssign(areaId) pasa a "assigning" (deshabilita el select).
  2. action addDocumentToArea(documentId, areaId) documents.actions.ts
    service documentsProvider.addDocumentToArea(documentId, areaId): INSERT en document_areas.
    • 23505 (la pareja ya existía) → se trata como éxito.
    • 42501 → AccessError 403.
    • 23503 (documento o área inexistente) → DocumentError.AssignAreaFailed 404.
  3. cliente Agrega el areaId a assignedIds. El área aparece como pellet y sale del dropdown.

La card calcula los pellets como areas.filter(a => assignedIds.includes(a.id)): si un área se renombra, el pellet muestra el nombre nuevo; si se borra, desaparece.

Esta función vive en el módulo documents porque la relación documento-área define quién puede ver el documento; el módulo areas se mantiene como catálogo.

2.4 Navegar carpetas

Las carpetas forman un árbol: cada fila de folders apunta a su padre con parent_id; NULL significa que cuelga de la raíz. La raíz no es una fila: en la UI se llama "Documentos".

Ruta: src/app/DMS/documents/[[...folderId]]/page.tsx (catch-all opcional, Server Component).

URLfolderIdMuestra
/DMS/documentsnullRaíz: carpetas con parent_id IS NULL y documentos con folder_id IS NULL.
/DMS/documents/<uuid><uuid>Contenido directo de esa carpeta.
/DMS/documents/a/b o id que no es UUID—notFound() (404) sin consultar la base.
  1. servidor DocumentsFolderPage valida los segmentos con UUID_PATTERN. Mientras carga, Next muestra loading.tsx (skeleton con la misma sangría).
  2. service foldersProvider.getFolderElements(folderId) → supabase.rpc('get_folder_documents', { p_folder_id }). La página llama al provider directamente (es Server Component; no pasa por una action).
  3. db get_folder_documents (SECURITY INVOKER):
    • Chequea can_access_documents() (hoy: hay sesión). Si no, 42501.
    • Junta ids de subcarpetas directas y de documentos directos con deleted_at IS NULL y uploaded_at IS NOT NULL.
    • Si no es la raíz, recorre la carpeta y sus ancestros (WITH RECURSIVE + CYCLE) para armar path (raíz → actual) y las áreas heredadas.
    • Devuelve { path, folders, documents } en JSON; cada elemento trae tags = áreas propias ∪ heredadas, ordenadas y sin repetidos.
  4. servidor Si hay folderId pero path llegó vacío, la carpeta no existe → notFound() (fuera del try, porque funciona lanzando). Un error de la consulta se muestra en la página con handleError(...).message.
  5. render FolderBreadcrumbs (Documentos › … › actual), link "Regresar a <padre>" (el penúltimo de path), título con CreateFolderButton, y la lista: primero FolderRow (link a /DMS/documents/<id> + Editar), luego DocumentRow (Ver, Descargar, Editar).

Botón "Volver" del layout. DmsShell.tsx pinta BackButton en toda ruta del DMS menos /DMS. Dentro de /DMS/documents/** le pasa href="/DMS", así que "Volver" siempre lleva al inicio (si usara router.back() regresaría carpeta por carpeta). Para subir un nivel están el breadcrumb y "Regresar a …".

2.5 Crear una carpeta

Punto de entrada: CreateFolderButton (src/components/DMS/CreateFolderButton.tsx), junto al nombre de la carpeta actual. Solo se pinta si isAdminRole(user.role); esconderlo es presentación, RLS decide.

  1. cliente Abre DmsDialog con el input "Nombre". La carpeta nueva se crea dentro de la que se está viendo (parentId = folderId de la página, null en la raíz).
  2. action createFolder(folderName, parentId) src/app/DMS/admin/folders/folders.actions.ts: hace trim(); vacío → FOLDER_NAME_REQUIRED sin llamar a la base.
  3. service foldersProvider.createFolder: INSERT INTO folders (folder_name, parent_id); created_by lo pone el DEFAULT auth.uid().
    • 42501 → AccessError 403 (RLS folders_insert = is_admin()).
    • 23505 → FolderError.CreateFailed 409 (ya hay una carpeta con ese nombre en el mismo padre).
    • 23503 → CreateFailed 404 (el padre no existe).
  4. action refreshFolderPages() (ver 2.8) y devuelve { ok: true }.
  5. cliente Cierra el diálogo; la página se vuelve a pintar con la carpeta nueva.

La carpeta nueva no tiene áreas propias; hereda las de sus ancestros. Las propias se agregan con "Editar".

2.6 Editar una carpeta o un documento

Punto de entrada: EditItemButton (src/components/DMS/EditItemButton.tsx), en cada FolderRow y DocumentRow (también en "Documentos recientes" de /DMS). Solo admin. Un mismo diálogo cambia nombre, ubicación y áreas propias; mover es cambiar la ubicación.

Al abrir el diálogo

  1. cliente handleOpenChange(true) reinicia el formulario con el nombre y la carpeta actuales, vacía destinations y pone isLoading.
  2. action getEditOptions({ kind, id }) corre en paralelo:
    • foldersProvider.listAllFolders() — SELECT id, folder_name, parent_id FROM folders.
    • areasProvider.fetchAllAreas().
    • getFolderAreaIds(id) o documentsProvider.getDocumentAreaIds(id) — solo las áreas propias.
    Con las carpetas, buildDestinations(folders, excludeFolderId) arma la ruta de cada una ("Documentos / Calidad / Auditorías"), ordena con localeCompare('es') y pone la raíz primero. Si se edita una carpeta, quita a esa carpeta y a todas sus descendientes (moverla ahí formaría un ciclo).
  3. cliente Llena el select "Ubicación" ("" representa la raíz, porque un <option> no puede valer null) y los chips de "Áreas". Mientras destinations está vacío, "Guardar" queda deshabilitado.

Al guardar

  1. action updateFolder(folderId, { folderName, parentId, areaIds }) o updateDocument(documentId, { name, folderId, areaIds }): trim() del nombre; vacío → FOLDER_NAME_REQUIRED / DOCUMENT_NAME_REQUIRED.
  2. service supabase.rpc('update_folder' | 'update_document', …).
  3. db En una sola transacción (si algo falla, no se guarda nada):
    • is_admin() o 42501. Está explícito porque en un UPDATE, RLS no da error: solo filtra la fila.
    • UPDATE nombre y padre/carpeta. 0 filas → P0002. En documentos solo si deleted_at IS NULL, y pone updated_at = now().
    • Al cambiar parent_id se dispara el trigger folders_prevent_cycle → 23514 si el destino es una subcarpeta.
    • p_area_ids es la lista completa: DELETE de las áreas propias que no vienen, INSERT … ON CONFLICT DO NOTHING de las nuevas.
  4. action refreshFolderPages(); el diálogo se cierra con { ok: true } o muestra message.
CódigoCarpeta → mensajeDocumento → mensaje

P0002FolderError.UpdateFailed 404 "No se encontró la carpeta."DocumentError.UpdateFailed 404 (no existe o está eliminado)

2.7 Herencia de áreas

  • Áreas propias: filas en folder_areas (carpetas) o document_areas (documentos). Son las que muestra y edita el diálogo "Editar".
  • Áreas heredadas: las propias de todas las carpetas ancestro. No se guardan en ningún lado: get_folder_documents las calcula en cada consulta.
  • Los tags que ve la lista son propias ∪ heredadas. Por eso una etiqueta que aparece en una fila puede no estar marcada en su diálogo: se quita editando la carpeta de arriba que la aporta.
  • Mover una carpeta o documento cambia sus heredadas automáticamente (cambian sus ancestros); las propias viajan con él.
  • Hoy los tags son informativos: la lectura no se restringe por área (can_access_documents() solo pide sesión).

2.8 Caché de navegación y refresco

  • next.config.ts → experimental.staleTimes.dynamic = 120: el navegador reusa una carpeta ya visitada durante 120 s sin volver a pedirla (Router Cache). Navegar de ida y vuelta entre carpetas no consulta la base cada vez.
  • Toda action que escribe en carpetas llama refreshFolderPages(): 
    revalidatePath('/DMS/documents', 'layout') // la raíz y todas las carpetas ([[...folderId]])
revalidatePath('/DMS')                      // "Documentos recientes" también muestra nombre y tags
    Esto limpia el caché de quien hizo el cambio. Otros usuarios ven el cambio cuando vencen sus 120 s o recargan.

Documents service

Inserta en document_areas. Idempotente (un duplicado es éxito).

5. Manejo de errores

Jerarquía

AppError (src/lib/errors/base.ts, abstracta) tiene:

  • code — identificador estable (valor de un enum).
  • detail — texto técnico para logs. Nunca llega al usuario.
  • genericMessage — texto para el usuario.
  • statusCode — HTTP equivalente.

Subclases y sus códigos:

ClaseArchivoCódigos usados en este módulo
AuthErrorerrors/auth.tsAuthenticationFailure (sin sesión)
AccessErrorerrors/access.tsAuthorizationFailure (sin permiso), RoleCheckFailed (falló la consulta de rol)
DocumentErrorerrors/documents.tsCreateFailed, ConfirmFailed, UploadNotPending, AssignAreaFailed, UpdateFailed

Recorrido de un error

Postgres error.code ──► service: throw new XxxError(code, detail, genericMessage, status)
                         │
                         ▼
action catch: console.error(`[action] ${code} (${status}): ${detail}`)   → logs del servidor
              return { ok: false, code, message: genericMessage }       → navegador
                         │
                         ▼
componente: setError(result.message); status = "error"

Errores que no son AppError se registran completos y devuelven code: 'UNEXPECTED_ERROR'. En el componente, un catch alrededor de la action atrapa fallas de red, de CORS o de una action que no llegó al servidor.

Códigos de Postgres que se traducen

CódigoSignificadoCuándo aparece
42501insufficient_privilegeRLS rechaza un INSERT, o falta un GRANT en la tabla.
23505unique_violationNombre de área repetido; id de documento repetido; pareja documento-área repetida.
23503foreign_key_violationAsignar un área o documento que no existe; carpeta destino inexistente; borrar una carpeta con hijas o documentos.
23514check_violationMover una carpeta dentro de sí misma o de una subcarpeta (trigger y CHECK de folders).
P0002no_data_foundLo lanzan update_folder/update_document cuando el elemento no existe.
RLS en UPDATE, DELETE y SELECT no produce error. Filtra las filas en silencio: el UPDATE o DELETE afecta 0 filas y el SELECT devuelve menos filas (o ninguna). Por eso editArea, deleteArea y confirmUpload encadenan .select('id') y tratan 0 filas como error, y por eso un no-admin recibe [] en fetchAllAreas. Encadenar .select() exige además que la fila pase la política de SELECT.

Requisitos de R2

  • CORS del bucket: debe permitir PUT con el header content-type desde el dominio de producción y desde http://localhost:3000. Sin esto, el paso 3 de la subida falla en el navegador con un TypeError (sin respuesta HTTP).
  • Checksums: el S3Client usa requestChecksumCalculation: 'WHEN_REQUIRED'. Con el valor por defecto, el SDK agrega a las URLs firmadas un checksum que el navegador no envía y R2 rechaza.

7. Cómo extender

Aceptar un nuevo tipo de archivo
Agregar el MIME a SupportedFileTypes y su extensión a FILE_SUFFIX (TypeScript obliga a hacer ambos). El accept del input y la validación del componente se actualizan solos.
Agregar una operación de áreas
(1) Firma en AreasProvider. (2) Implementación en SupabaseAreasService, traduciendo 42501 con insufficientPrivilege y usando .select() si es UPDATE o DELETE. (3) Código en AreaErrorCode si hace falta. (4) Action en areas.actions.ts con toActionError. (5) Si cambia la lista, llamar onChanged/loadAreas desde el componente.
Mostrar más columnas de un área
Agregar la columna al Pick de Area y al .select('id, name, …') de fetchAllAreas.
Quitar un área de un documento
Agregar removeDocumentFromArea en DocumentsProvider/service (DELETE … RETURNING, 0 filas = no estaba asignada o sin permiso), su action en documents.actions.ts, y un botón en el pellet de UploadedDocumentCard que lo saque de assignedIds.
Dar a usuarios normales acceso de lectura a áreas
Cambiar la política areas_select en una migración nueva. El código no necesita cambios porque no valida el rol.
Cambiar quién puede subir documentos
Cambiar la RPC has_full_document_access y la política documents_insert. Hoy el service consulta la RPC y RLS vuelve a validar en el insert; si solo se cambia una, la otra seguirá bloqueando.
Agregar un campo al diálogo "Editar"
(1) Parámetro nuevo en update_folder/update_document (migración nueva con CREATE OR REPLACE; si cambia la firma, borrar la anterior). (2) Campo en UpdateFolderInput/UpdateDocumentInput y en el rpc() del service. (3) Si necesita datos para precargarse, agregarlos a getEditOptions. (4) Estado + DmsDialogField en EditItemButton.
Borrar carpetas desde la UI
La action deleteFolder ya existe. Falta un botón (por ejemplo, otro DmsDialog de confirmación). La base rechaza carpetas con contenido (23503).
Restringir la lectura por área
Cambiar can_access_documents() y las políticas SELECT de folders/documents; la herencia ya se calcula en get_folder_documents. Ver el TODO de ADR-011.
Un formulario nuevo en diálogo
Usar DmsDialog con children, DmsDialogField por campo y DMS_DIALOG_CONTROL en inputs/selects. El componente que lo usa controla open y el estado del formulario.

8. Comportamientos no obvios y límites actuales

ComportamientoConsecuencia
No existe limpieza de subidas pendientes. El cron hard-delete-documents solo procesa filas con deleted_at; no toca filas con uploaded_at IS NULL.Una subida que falla después del paso 2 deja una fila pendiente para siempre (y quizá un objeto en R2). Las consultas de listado deben filtrar uploaded_at IS NOT NULL.
El tipo de archivo solo se valida en el navegador.uploadDocument confía en fileType. Un tipo no soportado haría que FILE_SUFFIX[fileType] sea undefined y la key termine en "undefined".
La confirmación no verifica que el objeto exista en R2.Se confía en que el navegador recibió response.ok del PUT.
Las áreas asignadas de la card viven en estado local (assignedIds).Al recargar la página la card desaparece. Las asignaciones sí persisten en document_areas, pero no hay consulta que las lea.
fetchAllAreas se llama al montar AdminPanel y después de cada cambio.Cambios hechos por otro admin no se ven hasta que pase uno de esos dos eventos.
areas.name es único exacto."Marketing" y "marketing" pueden coexistir.
El comentario de areas_select en la migración dice "cualquier usuario autenticado".La política real es is_admin(); el comentario está desactualizado.
Los tags heredados no aparecen marcados en el diálogo "Editar".Solo se editan las áreas propias. Para quitar un tag heredado hay que editar la carpeta ancestro que lo aporta.
getEditOptions trae todas las carpetas cada vez que se abre "Editar".Con muchas carpetas el diálogo tardará más en cargar. No hay caché ni paginación.
refreshFolderPages() solo limpia el Router Cache de quien hizo el cambio.Otros usuarios pueden ver la versión anterior de una carpeta hasta 120 s.
Un documento eliminado (soft delete) pierde su carpeta.Al recuperarlo queda en la raíz; hay que moverlo con "Editar".
La lectura de carpetas y documentos no se filtra por área.Todo usuario con sesión ve todo el árbol (can_access_documents()).
Los colores soma-cream, soma-line, etc. viven en @theme de globals.css.Si se agrega un token y el dev server no reconstruye el CSS, las clases no existen y el diálogo se ve transparente. Reiniciar npm run dev (o borrar .next).
supabase/seed.sql tiene <LOCAL_SECRET_KEY> en lugar de la key local.En local, el cron no se autentica hasta que se reemplaza por el valor de npx supabase status (sin hacer commit de ese cambio).

9. Glosario

Área
Grupo de la empresa. Un documento puede tener varias (document_areas); un usuario tiene una (profiles.area_id).
Raíz ("Documentos")
Nivel superior del árbol. No es una fila: son las carpetas con parent_id IS NULL y los documentos con folder_id IS NULL. URL /DMS/documents.
Área propia / área heredada
Propia: asignada directamente a la carpeta o documento (folder_areas, document_areas). Heredada: propia de alguna carpeta ancestro; se calcula al consultar.
Tags
En la UI, los nombres de las áreas (propias ∪ heredadas) que se muestran como badges.
Router Cache
Caché del navegador de Next para páginas ya visitadas. Su duración la fija staleTimes; revalidatePath lo limpia.
Fila pendiente
Fila de documents con uploaded_at IS NULL: el documento está reservado pero su archivo no se ha confirmado.
Key
Ruta de un objeto dentro del bucket de R2 (documents/<uuid>.pdf). Se guarda en documents.file_path.
URL firmada (presigned URL)
URL temporal generada en el servidor que autoriza una sola operación sobre una key (subir o descargar) sin exponer credenciales.
RLS (Row Level Security)
Políticas de Postgres que deciden, por fila y por operación, qué puede hacer el usuario de la sesión. Fuente de verdad de los permisos.
RPC
Función SQL llamada desde código con supabase.rpc('nombre').
Provider / Service
Provider: interfaz TypeScript con las operaciones de un módulo. Service: su implementación concreta para Supabase o R2.
Server Action
Función async en un archivo 'use server'. Se llama desde el navegador como si fuera local, pero corre en el servidor.
Cliente de sesión
El cliente de Supabase de createSupabaseServerClient(): actúa como el usuario del request, por lo que RLS aplica.
Idempotente
Que repetir la operación no cambia el resultado. Aplica a confirmUpload y addDocumentToArea.
Referencia de docs/. Las decisiones de arquitectura de fondo están en docs/decisions/ (en particular ADR-005, ADR-008, ADR-010 y ADR-011). La gestión de usuarios está en funcionamiento-gestion-de-usuarios.html.
